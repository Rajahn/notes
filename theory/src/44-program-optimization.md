# 第 44 章　程序级优化

## 本章导引

### 这一章要做什么

上一章把一个提示词当作要调的参数。真实的系统很少只有一个提示词。售后定责系统至少有三步：从买家描述和照片里**读出**"是否腐烂""包装是否破损渗汁"这些事实，从订单字段里**算出**"是否在 48 小时内"，再由**规则**给出结论，拿不准时转人工。前两步各有自己的提示词、示例和模型，第三步有自己的阈值和分支。整个东西是一个**程序**，语言模型只是其中几个部件。

把这样一个程序作为整体来优化，会遇到单个提示词没有的问题：

- 只有最终结论有标签，中间每一步"读得对不对"没有人告诉我们。成绩变好了，该归功于哪个模块？成绩变差了，该改哪个模块？
- 模块之间互相牵制。只改读取器的输出格式，规则就解析不了；只改规则，读取器的新能力又用不上。一次只改一个模块，会不会卡住？
- 优化器只看最终结论时，会不会把读取器"训练"成直接猜结论，让本该测量事实的部件变成夹带结论的部件？

这一章先介绍几种代表性的方法：DSPy 的签名、模块与优化器，MIPRO 用贝叶斯优化联合挑指令与示例，TextGrad 与 Trace 的"文本梯度"，GEPA 的反思式进化。然后用售后例子把上面三个问题逐一形式化：自举示例在什么情况下会收进错误的示例（命题 44.1），分块坐标优化停在哪里（命题 44.3），小批量上的接受规则需要多大的门槛（命题 44.4），模块替换怎样分配功劳（命题 44.6），端到端优化读取器为什么会把读数推向结论（命题 44.7），以及分开优化为什么仍然有保证（引理 44.8）。

### 读完这一章，你会知道

1. 什么是 LLM 程序，它的参数有哪些，程序级优化问题由哪几样东西组成。
2. DSPy、MIPRO、TextGrad、Trace、GEPA 各自优化什么、用什么信号、怎样搜索，以及哪些细节需要以原文为准。
3. "从成功轨迹里收集示例"在什么情况下会收进错误的示例，只保留关键案例能挡住多少。
4. 一次改一个模块的坐标优化一定会停下，但可能停在一个任何单步修改都改进不了的差解上；小批量评估时接受门槛要多大。
5. 只看最终结论、联合优化读取器和规则，会使读取器在碰撞案例上故意读错，训练代价降到碰撞下界以下；分开优化时，读取误差直接给出成绩损失的上界。
6. 怎样在模块之间分配功劳，怎样把调用成本和转人工率放进目标里。

### 本章新词

| 词 | 一句话解释 |
|---|---|
| LLM 程序（复合系统） | 由若干次语言模型调用和普通代码组成的程序 |
| 签名 | 一个模块"输入哪些字段、输出哪些字段"的声明 |
| 模块 | 程序中的一步，带自己的指令、示例和模型选择 |
| 优化器 | 根据数据和指标自动改模块参数的算法 |
| 自举示例 | 让程序自己跑训练案例，从成功的运行里截取各模块的输入输出当示例 |
| 关键案例 | 某个模块换一个输出、最终结论就跟着变的案例 |
| 块坐标优化 | 一次只改一个模块的参数，其余固定，轮流进行 |
| 块坐标局部最优 | 单独改任何一个模块都不能更好的参数组合 |
| 文本梯度 | 由语言模型写出的"这个变量应当怎样改"的文字反馈 |
| 执行迹 | 一次运行中参数、中间结果与输出之间的计算图 |
| 实例级帕累托前沿 | 在至少一个案例上取得最好成绩、且不被别的候选全面压过的候选 |
| 模块替换 | 把某个模块的输出换成核实过的正确值，看最终成绩变化多少 |

## 44.1 从一个提示到一个程序

### 44.1.1 售后定责是一个程序

把售后系统写成几行伪代码：

```python
def 定责(订单, 描述, 照片):
    a = 在时限内(订单.签收时间, 订单.申请时间)          # 普通代码
    证据 = 抽取证据(描述, 照片)                          # 语言模型调用 1
    b = 读取("是否腐烂", 证据)                           # 语言模型调用 2
    p = 读取("包装是否破损且有汁液渗出", 证据)           # 语言模型调用 3
    return 规则(a, b, p)                                 # 普通代码：规则丙
```

这里的规则丙是"不在时限内 → O；腐烂或渗汁 → S；否则 → B"。三次模型调用各有可以调的东西：指令文字、放进提示里的示例及其顺序、用哪个模型（例如虚构的 `lm-small-2026-01` 或 `lm-large-2026-01`）、温度。规则也有可以调的东西：用规则甲、乙还是丙，"无法判断"时转不转人工。

### 44.1.2 定义

**定义 44.1（LLM 程序）** 一个 **LLM 程序**由有限个**模块** $m_1,\dots,m_M$ 和把它们连起来的普通代码组成。每个模块有一个**签名**：输入字段和输出字段的名称与类型。模块 $m_j$ 的**参数** $\theta_j$ 是它的指令、示例列表、模型选择与解码设置；普通代码里可调的常数（阈值、规则的选择）也算参数。对输入 $x$，程序以参数 $\theta=(\theta_1,\dots,\theta_M)$ 运行，产生输出 $\Phi_\theta(x)$ 和一条**执行迹** $\tau_\theta(x)$，记录每个模块收到了什么、输出了什么。

**怎么读**：上面的伪代码里 $M=4$（三个模型模块加规则），$\theta_2$ 是"读腐烂"的指令和示例，$\theta_4\in\{\text{甲},\text{乙},\text{丙}\}$。执行迹就是第 18 章读数回执的串联：每一步一张回执。

**定义 44.2（程序优化问题）** 给定参数空间 $\Theta=\Theta_1\times\dots\times\Theta_M$、一个**指标** $\mu(x,y,\Phi_\theta(x),\tau_\theta(x))$（越小越好；常取代价 $c(y,\Phi_\theta(x))$）和训练样本 $S$，**程序优化问题**是

$$
\begin{aligned}
&\min_{\theta\in\Theta}\ \hat J_S(\theta),\\
&\hat J_S(\theta)=\frac1n\sum_{i=1}^n\mu\big(x_i,y_i,\Phi_\theta(x_i),\tau_\theta(x_i)\big).
\end{aligned}
$$

真正关心的是 $J(\theta)=\mathbb{E}\,\mu$，即程序在将来案例上的风险。

**怎么读**：$\hat J_S$ 就是第 1 章的经验风险，只不过"假设"换成了一组程序参数。两点与第 1 章不同。第一，$\Theta_j$ 往往是"语言模型能写出的任何一段指令"，没有梯度，评估一次要真正调用模型，很贵。第二，$y_i$ 只是**最终结论**的标签；中间模块输出的对错，一般没有标签。下面几节的困难几乎都来自这两点。

"复合系统"这个说法来自 Zaharia 等人 2024 年的一篇博客文章，指"由多次模型调用、检索器和外部工具组成的系统"。本章的 LLM 程序是它的一个特例：模块之间的连接是写死的代码，不由模型临时决定。

### 小结

这一节说的是：售后系统是一个由读取模块和规则组成的程序；程序优化就是在各模块参数的乘积空间上最小化经验风险，难点在于没有梯度、评估昂贵，以及只有最终结论有标签。

## 44.2 DSPy：签名、模块与优化器

### 44.2.1 把"怎么问"从程序里拿出来

手写提示词的程序有一个毛病：提示词的文字和程序的逻辑缠在一起。换一个模型，几十处提示词要重写；加一个步骤，前后的示例都要改。DSPy（Khattab 等，ICLR 2024）的主张是把两者分开：程序员只写**签名**和**模块**，提示词由**优化器**根据数据生成。

- **签名**是一行声明，例如 `证据 -> 是否腐烂: bool`，可以附一句说明。它只说"要什么"，不说"怎么问"。
- **模块**把签名变成一次具体的调用。最简单的 `Predict` 直接按签名提问；`ChainOfThought` 在输出字段前加一个"推理"字段；还有调用工具的模块。模块可以像神经网络的层那样组合成程序。
- **优化器**（早期版本叫 teleprompter）输入程序、训练样本和指标，输出参数更新后的程序。DSPy 的原文把这一步叫作"编译"。

售后程序在这种写法下大致是这样（示意，不是某个版本的确切接口；模型标识是虚构的）：

```python
读腐烂 = ChainOfThought("证据 -> 是否腐烂: bool")
读渗汁 = Predict("证据 -> 包装是否破损且有汁液渗出: bool")

def 定责(订单, 证据):
    a = 在时限内(订单)
    b = 读腐烂(证据=证据).是否腐烂
    p = 读渗汁(证据=证据).包装是否破损且有汁液渗出
    return 规则丙(a, b, p)

配置模型("lm-small-2026-01")
编译后 = 优化器(指标=结论一致, 训练集=S).compile(定责)
```

程序里没有一句"请判断下面的描述是否……"。这句话和放在它前面的示例，都由优化器决定。

### 44.2.2 原文中的几种优化器

原文的核心优化器是**自举少样本**（`BootstrapFewShot`）：用当前程序（或另一个"教师"程序）跑训练案例，凡是最终指标通过的运行，就把其中每个模块的输入和输出截下来，作为这个模块的示例。在它之上还有：在多个自举示例集之间做随机搜索并在验证集上挑最好的；把自举出的轨迹拿去微调一个较小的模型。后续版本又加入了改写指令的优化器、本章 44.4 节的 MIPRO、44.7 节的 GEPA，以及交替进行权重微调与提示优化的 BetterTogether（Soylu、Potts、Khattab，EMNLP 2024）。各优化器的默认设置在不同版本之间变化很大，引用时要写清版本。

原文在多跳问答、数学文字题等任务上比较了编译前后和手写提示的程序，报告编译后的程序普遍更好。具体数字依赖模型、任务和版本，这里不转述。

### 44.2.3 它把问题变成了什么

从本书的角度看，DSPy 做了两件事。第一，它把"提示词"拆成了每个模块的 $\theta_j$，并且让示例成为参数的主要部分：示例是从训练案例中挑出来的，所以 $\Theta_j$ 在看数据之前就是"训练案例的子集及其排列"，这是一个有限的、可以记账的空间。第二，它给了一个解决"中间步骤没有标签"的办法：**用最终指标的通过与否，替中间步骤打分**。下一节分析这个办法。

### 小结

这一节说的是：DSPy 让程序员写签名和模块，由优化器按数据和指标生成各模块的指令与示例；它的核心优化器从成功运行中自举示例，用最终指标替中间步骤打分。

## 44.3 自举示例与功劳分配

### 44.3.1 一条成功的运行，每一步都对吗

用第 1 章的 8 个案例，规则甲（"不在时限内 → O；否则腐烂 → S；否则 → B"），$a$ 由订单字段算出，总是对的；$b$ 由读取器读出。假设读取器在其他案例上都读对，只把案例 3 和案例 7 的"腐烂"读成了"不腐烂"。

- 案例 7：$a=0$，规则直接判 O，与标签一致。运行"成功"，于是"案例 7 的描述 → 不腐烂"被收为读取器的示例。可这个描述里写着腐烂。
- 案例 3：真实 $b=1$，规则甲本应判 S，标签却是 B（第 1 章的碰撞组）。读取器读成 0，规则判 B，与标签一致。运行"成功"，"案例 3 的描述 → 不腐烂"也被收为示例。
- 如果读取器把案例 3 读对，规则判 S，运行失败，示例反而不收。

一个示例集就这样收进了两个错误示例，而且错的方式不同：案例 7 的错误是**放过**（结论与 $b$ 无关，读成什么都通过），案例 3 的错误是**奖励**（读错才通过）。

### 44.3.2 定义

**定义 44.3（自举示例）** 给定程序 $\Phi_\theta$、训练样本 $S$ 和一个"通过"判据 $\mathrm{pass}(y,\hat y)$（例如 $\hat y=y$）。对每个 $i$ 运行程序；若 $\mathrm{pass}(y_i,\Phi_\theta(x_i))$，则对每个模块 $j$，把执行迹中 $m_j$ 的（输入，输出）加入 $m_j$ 的候选示例池。

**定义 44.4（关键案例）** 固定其他模块的实际输出。若把模块 $j$ 在案例 $i$ 上的输出换成另一个可能的值，程序的最终输出会改变，就说案例 $i$ 对模块 $j$ 是**关键的**。

**怎么读**：关键就是第 36 章"但若检验"在模块输出上的版本。在规则甲下，$a=1$ 的案例（1–6）对 $b$ 的读取器是关键的，$a=0$ 的案例（7、8）不是。

### 44.3.3 关键案例上，通过等于"与标签一致的那个值"

**命题 44.1（关键案例上的自举）** 设模块 $j$ 输出二值事实，其他模块的输出固定，最终输出是这些输出的确定函数 $g$，通过判据是 $\hat y=y$。对模块 $j$ 关键的案例 $i$，记真实事实为 $z_i$，其他模块的实际输出为 $w_i$。则：

1. 至多有一个值 $v\in\{0,1\}$ 使运行通过；
2. 若 $g(w_i,z_i)=y_i$（**标签与规则一致**），运行通过当且仅当模块输出 $z_i$；
3. 若 $g(w_i,z_i)\ne y_i$ 而 $g(w_i,1-z_i)=y_i$，运行通过当且仅当模块输出 $1-z_i$，即读错。

对不关键的案例，两个值的通过与否相同，通过不提供关于模块 $j$ 对错的任何信息。

#### 证明（第一遍可以跳过）

**思路**：关键意味着两个输出给出两个不同的结论，至多一个等于标签。

1. 关键：$g(w_i,0)\ne g(w_i,1)$，两个结论不同，至多一个等于 $y_i$，这是第 1 条。
2. 若 $g(w_i,z_i)=y_i$，由第 1 条，$1-z_i$ 给出的结论不等于 $y_i$，所以通过当且仅当输出 $z_i$，这是第 2 条。第 3 条同理。
3. 不关键：$g(w_i,0)=g(w_i,1)$，两个输出给出同一结论，通过与否相同。$\square$

**代入例子**：第 2 条对应案例 1、2、4、5；第 3 条对应案例 3（读错才得 B）和案例 6（真实不腐烂，规则甲判 B，标签是 S；读成腐烂才通过）；案例 7、8 不关键。所以，只从关键案例收示例，能挡住"放过"，挡不住"奖励"：标签与"规则用真实事实"不一致的地方，自举会系统地收进读错的示例。这样的地方恰好是碰撞组和规则写错的地方。

### 44.3.4 收进来的示例有多少是错的

把上面的确定性结论放进一个概率模型。设：案例以概率 $s$ 对模块 $j$ 不关键，在不关键的案例上程序以概率 $\kappa_0$ 通过；模块独立地以概率 $\varepsilon$ 读错；在关键案例上，标签以概率 $\rho$ 与规则不一致；三者相互独立。

**推论 44.2（自举示例的错误率）** 在上述模型下，被收进示例池的模块 $j$ 示例中，错误示例的比例是

$$
\begin{aligned}
&\Pr(\text{读错}\mid\text{通过})\\
&\quad=\frac{s\kappa_0\varepsilon+(1-s)\varepsilon\rho}{s\kappa_0+(1-s)\big[(1-\varepsilon)(1-\rho)+\varepsilon\rho\big]} .
\end{aligned}
$$

只从关键案例收示例时，比例是 $\varepsilon\rho/\big[(1-\varepsilon)(1-\rho)+\varepsilon\rho\big]$。

**怎么读**：分子是"读错且通过"的概率：不关键时读错照样通过（$s\kappa_0\varepsilon$），关键时读错要碰上标签不一致才通过（$(1-s)\varepsilon\rho$）。分母是通过的总概率，关键案例上通过的两种方式由命题 44.1 第 2、3 条给出。代入 $s=0.3$（三成案例超出时限）、$\kappa_0=1$、$\varepsilon=0.15$、$\rho=0.1$：通过率 $0.846$，错误示例比例 $0.0555/0.846\approx0.066$；只收关键案例时降到 $0.0150/0.78\approx0.019$；若 $\rho=0$，这个比例为 0。读取器本身读错 15%，自举能把示例的错误率压低，这正是它有用的原因；压不到 0 的部分，来自不关键的案例和标签与规则不一致的案例。

#### 证明（第一遍可以跳过）

由全概率公式按"是否关键"分开。不关键时，通过的概率是 $\kappa_0$，与读对读错无关，"读错且通过"的概率为 $s\kappa_0\varepsilon$。关键时，由命题 44.1，通过当且仅当"读对且一致"或"读错且不一致"，概率分别为 $(1-\varepsilon)(1-\rho)$ 和 $\varepsilon\rho$。两部分相加得分母，读错的部分相加得分子，相除即得。只收关键案例时令 $s=0$。$\square$

### 44.3.5 功劳分配是这一章的主线

DSPy 的自举把"最终通过"的功劳平均分给了每一个模块的每一步。MIPRO 的原文把同一个困难明确称为**功劳分配**问题：只有程序级的指标，怎样判断哪个模块的哪个参数起了作用。后面几节的方法可以按它们怎样回答这个问题来区分：MIPRO 用代理模型从许多次组合评估中统计出来（44.4 节）；TextGrad 和 Trace 让语言模型读执行迹和反馈，用文字说出来（44.6 节）；GEPA 每次只改一个模块，让改动与成绩变化直接对应（44.7 节）；模块替换在有核实数据时把它量出来（44.8 节）。

### 小结

这一节说的是：从成功运行中自举示例，相当于用最终结论替每一步打分；在不关键的案例上这会"放过"错误，在标签与规则不一致的关键案例上会"奖励"错误（命题 44.1）；只收关键案例能去掉前者，去不掉后者（推论 44.2）。

## 44.4 MIPRO：联合挑指令与示例

### 44.4.1 方法

MIPRO（Opsahl-Ong 等，EMNLP 2024）优化多模块程序中每个模块的**指令**和**示例**，不需要模块级标签。按原文的描述，它分三步：

1. **自举示例候选**：用 44.3 节的办法为每个模块收集若干个候选示例集。
2. **提议指令候选**：让一个提议模型为每个模块写若干条候选指令。提议时给它看的不只是模块签名，还有对数据集的概括、对程序结构的概括、自举出的示例，以及随机抽取的写作"提示"，原文称之为"有根据的"提议。
3. **在组合上搜索**：每个模块从候选里各选一条指令、一个示例集，组成一个完整的程序配置；在训练集的**小批量**上评估，用一个贝叶斯代理模型（原文采用 Bergstra 等 2011 年的树结构 Parzen 估计器，TPE）根据历史评估决定下一个配置，每隔一段把当前最好的几个配置拿到更大的验证集上评估。

原文在多个多阶段程序上与只调示例、只调指令以及逐模块的 OPRO 式基线比较，报告联合优化在多数任务上更好；不同版本的论文报告的任务数和幅度不同，以原文为准。

### 44.4.2 为什么用代理模型

搜索空间是乘积。$M=3$ 个模块，每个有 10 条候选指令和 10 个候选示例集，组合数是 $(10\times10)^3=10^6$。每评估一个组合，要在一批案例上运行整个程序。穷举不可能；随机搜索（0.5 节）每次评估都不利用以前的结果。代理模型的作用是把"组合 → 成绩"的关系学成一个便宜的函数，在评估之间做功劳分配：如果含某条指令的组合普遍好，这条指令就值得多试。

TPE 的做法是把历史评估按成绩分成好、差两组，分别估计参数在两组中的分布，挑"在好组里常见、在差组里少见"的配置。常用的实现对各个参数分别估计分布，于是它对每个模块的选择接近于"按边际表现打分"。如果两个模块的选择之间有很强的交互（下一节的接口耦合就是一例），边际统计会把好的组合与坏的组合平均在一起，代理模型要靠更多的评估才能分辨。原文还提出一个元优化步骤：随着搜索进行，调整提议模型构造候选的方式；以及按历史选择、按小批量贪心等变体，这里不展开。

### 44.4.3 小批量评估的代价

在小批量上评估很省，但会带来两个问题。一是噪声。设配置甲、乙的真实准确率分别是 0.70 和 0.75：在 65% 的案例上两者都对，10% 只有乙对，5% 只有甲对，20% 都错。在 25 个案例的小批量上，甲严格胜出的概率约 0.175，打平或胜出约 0.350；100 个案例时分别约 0.074 和 0.119；400 个案例时约 0.004 和 0.005（按多项分布精确计算）。也就是说，25 个案例上的一次比较，有三分之一以上的机会认不出更好的那个。二是二是选择偏差：从大量配置里挑小批量上最好的，它的成绩偏乐观（第 1 章命题 1.2）。MIPRO 定期在更大的验证集上复核，是对第一个问题的回应。

验证集上的成绩能信到什么程度，取决于记账的方式。设验证集有 $n=1000$ 个案例，0-1 代价，$\delta=0.05$，用定理 2.7 的双侧形式。

- **验证结果不反馈给搜索**：搜索只看训练小批量，验证集只用来给最后的若干个配置打分、挑最好的。这时只需对验证集上评估过的 $k$ 个配置用联合界。$k=20$ 时余量 $\sqrt{\ln(2\times20/0.05)/(2\times1000)}\approx0.058$。
- **验证结果反馈给搜索，但候选池事先固定**：指令候选和示例候选都在看验证集之前生成好了，代理模型可以任意利用验证成绩。被选中的配置总在池里，所以对**整个池**用联合界，无论搜索怎样自适应都成立。$10^6$ 个组合时余量 $\sqrt{\ln(2\times10^6/0.05)/2000}\approx0.094$；验证集只有 300 个案例时约 0.171。
- **候选是看着验证结果新写出来的**：池不再事先固定，上面两种记账都不适用，要回到第 5 章的交互记录界，或者另留一份测试集。

第二种记账有一个容易被忽略的前提：池要真正有限且事先列出。如果"示例集"是"任意 4 个训练案例的有序组合"，200 个训练案例时每个模块有 $200\times199\times198\times197\approx1.55\times10^9$ 种，三个模块再加上各 10 条指令，余量升到约 0.19。所以 MIPRO 先自举出少数几个候选示例集、再在它们之间搜索，从记账的角度看也是有道理的。下一节的命题 44.4 给出"接受一个改动"需要多大的门槛；第二个问题，后面讲评估陷阱时会专门讨论。

### 小结

这一节说的是：MIPRO 为每个模块自举示例候选、让提议模型有根据地写指令候选，再用 TPE 代理模型在乘积空间上搜索，在小批量上评估、定期在验证集上复核；代理模型在评估之间做功劳分配，但对强交互的组合需要更多评估。

## 44.5 一次改一个模块：分块坐标优化

### 44.5.1 一个卡住的例子

很多程序优化器每一步只动一个模块：轮流为每个模块提新指令，或者每次挑一个模块做"反思式"改写。这很自然：一次动一个，改动和成绩变化的对应关系清楚。它的风险是模块之间的**接口**。

看售后系统里的两个模块。读取器 $r$ 有两个版本：$r_0$ 只输出"腐烂/不腐烂"；$r_1$ 在描述含糊时输出"无法判断"。规则 $g$ 也有两个版本：$g_0$ 是规则甲，解析读数时把一切不是"腐烂"的输出当作不腐烂；$g_1$ 是规则甲加"读数为无法判断 → 转人工"。设只看在时限内的案例：七成描述清楚，读取器读对 98%；三成描述含糊，二值读取器只读对 70%，三值读取器在含糊描述上一律回答"无法判断"。真实腐烂与否各占一半，代价矩阵照第 1 章（腐烂读成不腐烂，判 B 而实为 S，代价 3；反过来代价 1），转人工每单代价 0.3，人工判对。每单的期望代价：

| | $g_0$：无法判断当作不腐烂 | $g_1$：无法判断转人工 |
|---|---|---|
| $r_0$：二值读取 | 0.208 | 0.208 |
| $r_1$：三值读取 | 0.478 | 0.118 |

**怎么读**：$r_0$ 从不输出"无法判断"，所以两条规则对它一样，都是 $0.7\times0.02\times2+0.3\times0.3\times2=0.208$（2 是两种读错的平均代价）。$r_1$ 配 $g_0$ 时，含糊而实为腐烂的那一半被当作不腐烂，代价 $0.028+0.3\times0.5\times3=0.478$。$r_1$ 配 $g_1$ 时，含糊案例全部转人工，代价 $0.028+0.3\times0.3=0.118$，转人工率 30%。

从 $(r_0,g_0)$ 出发，只换读取器变差（0.478），只换规则不变（0.208）。如果规定"严格变好才接受"，坐标优化就停在 0.208，而最好的组合是 0.118。只有**同时**换两个模块才能走过去。

### 44.5.2 定义与命题

**定义 44.5（块坐标局部最优）** 参数 $\theta^\circ\in\Theta_1\times\dots\times\Theta_M$ 是目标 $f$ 的**块坐标局部最优**，如果对每个 $j$ 和每个 $\theta_j'\in\Theta_j$，

$$
f(\theta_j',\theta^\circ_{-j})\ge f(\theta^\circ),
$$

其中 $(\theta_j',\theta^\circ_{-j})$ 表示把第 $j$ 块换成 $\theta_j'$、其余不变。

**怎么读**：单独改任何一块都不能严格变好。上例中 $(r_0,g_0)$ 是块坐标局部最优，$(r_1,g_1)$ 也是，后者还是全局最优。0.5 节的局部最优是对一般"邻居"说的，这里的邻居是"只改一块"。在博弈论里，这就是所有玩家收益相同时的纳什均衡：没有一个模块能单方面改进。

**命题 44.3（块坐标优化停在块坐标局部最优）** 设每个 $\Theta_j$ 有限，$f$ 在一份固定的数据上精确计算。算法轮流考察 $j=1,\dots,M$：若 $\min_{\theta_j'}f(\theta_j',\theta_{-j})<f(\theta)$，把 $\theta_j$ 换成达到最小值的那个；否则不动。一整轮没有任何改动时停止。则：

1. $f$ 的值严格下降，算法在至多 $\lvert\Theta\rvert-1$ 次改动后停止；
2. 停止时的参数是块坐标局部最优；
3. 反过来，每个块坐标局部最优，从它出发时算法立即停止；因此最后停在哪一个，取决于起点和考察顺序；
4. 全局最优是块坐标局部最优，反之不成立，两者的差可以任意大。

#### 证明（第一遍可以跳过）

**思路**：值严格下降的序列不会重复访问同一个点，有限集合里只能走有限步。

1. 每次改动都使 $f$ 严格下降，所以访问过的参数两两不同（同一个点的 $f$ 值相同，不可能出现在严格下降序列的两个位置）。$\Theta$ 有限，改动至多 $\lvert\Theta\rvert-1$ 次。每一整轮要么有改动，要么停止，所以算法停止。
2. 停止时最后一整轮里每个 $j$ 都没有改动，即对每个 $j$ 都有 $\min_{\theta_j'}f(\theta_j',\theta_{-j})\ge f(\theta)$，这正是定义 44.5。
3. 若起点是块坐标局部最优，第一轮每个 $j$ 都满足"不动"的条件，算法立即停止。
4. 全局最优 $\theta^\ast$ 满足 $f(\theta^\ast)\le f(\theta)$ 对一切 $\theta$ 成立，特别对 $(\theta_j',\theta^\ast_{-j})$ 成立。反例：把上表推广为 $f(r_0,g_0)=f(r_0,g_1)=A$，$f(r_1,g_0)=B>A$，$f(r_1,g_1)=0$，$(r_0,g_0)$ 是块坐标局部最优，与全局最优差 $A$，$A$ 可以取任意正数。$\square$

**怎么用**：命题的前三条是好消息：只要评估是精确的、接受是严格的，坐标优化不会来回打转，一定在有限步内停下。第四条是坏消息：停下的地方只对"改一块"这种邻居最优。补救的办法都在扩大邻居或换起点：允许成对修改（每轮代价从 $\sum_j(\lvert\Theta_j\rvert-1)$ 增加到 $\sum_{j<k}\lvert\Theta_j\rvert\lvert\Theta_k\rvert$ 量级）；多个起点；或者让一次修改同时改动接口两侧（44.7 节 GEPA 的"合并"可以看作这样一种操作，但它合并的是各自演化过的模块，不保证接口兼容）。也可以从设计上消除接口耦合：先在签名里规定读取器输出三值，规则必须处理"无法判断"，这样 $g_1$ 是唯一可选的规则，坐标优化就不会卡在 $(r_0,g_0)$。

### 44.5.3 评估有噪声时

命题 44.3 要求 $f$ 精确计算。实际的优化器在小批量上比较当前程序和候选程序。噪声下"严格变好才接受"就不再保证单调：一个实际更差的候选可能在这一批上碰巧更好。办法是要求改进超过一个门槛，并且每一步用**新的**小批量。

**命题 44.4（带门槛的含噪接受）** 设代价取值于 $[0,C]$，$J$ 为真实风险。算法进行至多 $T$ 步，第 $t$ 步根据以往的一切选出至多 $K$ 个候选，再抽一个与以往一切独立的新小批量 $B_t\sim\mathcal{D}^b$，在 $B_t$ 上计算当前程序与每个候选的成对差值估计 $\hat\Delta=\hat J_{B_t}(\theta_t)-\hat J_{B_t}(\theta')$；若最大的 $\hat\Delta\ge\eta$，接受对应的候选。令

$$
\varepsilon=C\sqrt{\frac{2\ln(2TK/\delta)}{b}} .
$$

则以至少 $1-\delta$ 的概率：每个被接受的候选的真实改进 $J(\theta_t)-J(\theta')\ge\eta-\varepsilon$；每个真实改进至少 $\eta+\varepsilon$ 的候选，其估计都达到门槛，因此那一步一定会接受某个候选。若 $\eta>\varepsilon$，被接受的改动至多 $C/(\eta-\varepsilon)$ 次。

**怎么读**：$\varepsilon$ 是 $TK$ 次比较同时成立的估计误差。代入 0-1 代价（$C=1$）、$T=50$ 步、每步 $K=10$ 个候选、$\delta=0.05$：$\ln(2\times500/0.05)=\ln20\,000\approx9.90$。小批量 $b=200$ 时 $\varepsilon\approx0.315$，$b=2000$ 时约 $0.0995$，$b=5000$ 时约 $0.063$。也就是说，几百个案例的小批量，在这样的保证下只能确认几十个百分点的改进；"小批量上好了 2 个百分点"在这个界下什么也说明不了。

#### 证明（第一遍可以跳过）

**思路**：小批量是新抽的，候选在抽之前就定了，所以每次比较都是一个固定差值的霍夫丁估计；再对 $TK$ 次比较用联合界。

1. 固定第 $t$ 步和一个候选 $\theta'$。在给定以往一切的条件下，$\theta_t$ 和 $\theta'$ 已经确定，$B_t$ 与它们独立。每个案例的差值 $c(y,\Phi_{\theta_t}(x))-c(y,\Phi_{\theta'}(x))$ 取值于 $[-C,C]$，宽度 $2C$，期望为 $J(\theta_t)-J(\theta')$。
2. 霍夫丁不等式：$\Pr\big(\lvert\hat\Delta-\Delta\rvert\ge\varepsilon\big)\le2\exp\big(-2b\varepsilon^2/(2C)^2\big)=2\exp\big(-b\varepsilon^2/(2C^2)\big)$。代入 $\varepsilon$ 的定义，右边等于 $\delta/(TK)$。这个条件概率的界对以往的每种取值都成立，所以无条件也成立。
3. 联合界：$TK$ 次比较中至少一次误差达到 $\varepsilon$ 的概率不超过 $\delta$。以下在"全部误差小于 $\varepsilon$"的事件上讨论。
4. 被接受的候选有 $\hat\Delta\ge\eta$，所以 $\Delta>\eta-\varepsilon$。真实改进至少 $\eta+\varepsilon$ 的候选有 $\hat\Delta>\eta$，达到门槛。
5. 若 $\eta>\varepsilon$，每次接受使 $J$ 至少下降 $\eta-\varepsilon$；$J$ 取值于 $[0,C]$，所以接受次数不超过 $C/(\eta-\varepsilon)$。$\square$

两点说明。第一，如果每一步用的是**同一个**小批量，第 1 步的独立性就不成立：候选是看着这批案例上的结果选出来的，这时要按第 5 章定理 5.1 给交互记录记账，第 32 章推论 32.6 已经算过修复过程反复使用同一份验证测试的代价。第二，这个界很保守，因为它用了差值的最大宽度 $2C$。两个程序通常在绝大多数案例上给出同一结论，差值几乎处处为 0；只在判定不同的案例上估计（第 35 章命题 35.16），或用 0.3 节的 McNemar 检验，会紧得多。

### 小结

这一节说的是：一次改一个模块的坐标优化，在精确评估、严格接受时一定在有限步内停下，停在块坐标局部最优（命题 44.3），但接口耦合会让它停在差解上；评估有噪声时，要用新的小批量和超过 $\varepsilon$ 的门槛，才能保证每次接受都是真改进（命题 44.4）。

## 44.6 文本梯度：TextGrad 与 Trace

### 44.6.1 TextGrad：把反向传播搬到文字上

TextGrad（Yuksekgonul 等；预印本 2024，正式发表于 *Nature* 2025）把系统写成一张计算图：结点是文字变量（提示词、中间回答、代码、分子描述），边是语言模型调用或其他函数。前向运行得到输出，再由一个"损失"给出评价，这个损失本身可以是一段由语言模型写的批评。**反向**时，对每个变量，让语言模型读"这个变量、它产生的后继、后继收到的反馈"，写出"这个变量应当怎样改"的文字，称为**文本梯度**；沿图逐个往回传。最后由"文本梯度下降"这一步，让语言模型按收到的全部反馈重写变量。它的接口刻意模仿 PyTorch：变量、损失、`backward()`、优化器的 `step()`。

原文把它用在几类问题上：研究生水平的科学题，在测试时逐题改进答案；代码优化；提示词优化；分子设计；放射治疗计划。注意前两类是**测试时的改进**：变量是某一道题的答案，改好就用，不在案例之间复用。这和 Self-Refine、Reflexion 一类"模型批评自己的输出再重写"的方法同属一族。程序级优化指的是另一件事：变量是**跨案例复用**的参数（提示词、示例、规则），一次修改影响所有将来的案例。本章只讨论后者。

### 44.6.2 Trace：把执行迹交给优化器

Trace（Cheng、Nie、Swaminathan，NeurIPS 2024）提出了一个更一般的问题形式。

**定义 44.6（迹预言机优化）** **迹预言机优化**（OPTO）的每一轮，优化器给出参数 $\theta$，预言机返回执行迹 $\tau$（从参数到输出的计算图，含每个结点的值与所做的运算）和关于输出的**反馈** $f$（一个数、一段文字，或两者都有）。优化器只根据历史上的 $(\theta,\tau,f)$ 决定下一个参数。

**怎么读**：数值优化里，预言机返回函数值和梯度；黑盒优化里只返回函数值；OPTO 返回的是整条执行迹加任意形式的反馈。Trace 的论点是：执行迹之于这类优化，就像计算图之于自动微分。它的 Python 库在程序运行时自动记录计算图；基于它的优化器 OptoPrime 把相关的子图整理成类似代码的文本，连同反馈一起交给语言模型，让它直接提出新的参数值。原文把它用在数值优化、提示词优化、超参数调整、机器人控制器设计和代码调试上，报告它常常能与各领域的专用方法竞争。按我们的理解，OptoPrime 与 TextGrad 的主要区别是：前者一次把整张相关子图交给语言模型，后者沿图逐个结点传递反馈。

### 44.6.3 文本梯度不是梯度

"梯度"这个类比在三处不成立，每一处都有后果。

- **没有下降保证。** 数值梯度保证"沿负梯度走一小步，函数值下降"。文本梯度只是一个**提议**：语言模型认为这样改会更好。改完是否更好，必须再评估。所以这类方法在本书的框架里是 0.5 节的局部搜索，邻居由语言模型提出；要单调，就得加上命题 44.4 那样的接受检查。一些实现在验证集上比较、变差就退回，这正是这一步。
- **没有链式法则。** 数值反向传播的每个局部导数是精确的，乘起来就是整体导数。文字反馈传过几个结点，每一步都是一次重新解释，误差会累积，也可能指向错误的模块。这是 44.3 节功劳分配问题的另一种形式：语言模型说"是读取器的错"，未必是读取器的错（44.8 节）。
- **反馈来自具体的案例。** 文本梯度是对着某几个判错案例写出来的，按它修改，就是第 32 章的生成—验证式修复：很容易得到只修好这几个案例的"过拟合补丁"。

**在售后例子上走一遍。** 程序是"$a$ 由代码算出，读取器读 $b$，规则甲"，判错的是第 1 章的案例 6：真实结论 S，程序判 B。损失写成文字："应为卖家责任，判成了买家责任"。反向时，规则结点收到的文本梯度大致是"规则在不腐烂时判 B，这一单应判 S"；读取器结点收到的大致是"判 B 是因为读数为不腐烂，若读成腐烂结论就对了"。两条反馈都**说得通**，这正是第 31 章命题 31.11 的情形：只看结论，读错、规则错、缺事实各自都能单独解释这一单。可真实原因是第三种：案例 6 的卖家责任来自包装破损渗汁（事实 $p$），而程序里根本没有这个事实。如果优化器照着第二条反馈改读取器的指令，比如"有汁液时视为腐烂"，它就把 $p$ 偷偷并进了 $b$，读取器在金标上的一致率下降，这是 44.9 节要讲的泄漏的一个具体样子。

第三条要单独强调。把执行迹、判错的案例和反馈文字交给优化器，就是第 5 章 5.10 节的设计丙：提出方看到了逐个案例和标签，它从这些数据里得到的比特数无法有效界定。这样被看过的数据就是**设计集**，它上面的成绩不能当作泛化的证据；要有另一份只返回采纳决定的选择集，和一份封存的测试集。

### 小结

这一节说的是：TextGrad 让语言模型沿计算图逐个写出"该怎样改"的文字并据此重写变量，Trace 把执行迹和任意反馈一起交给语言模型优化器；文本梯度只是提议，没有下降保证，没有精确的链式法则，而且是对着具体案例写出的，看过的数据只能当设计集。

## 44.7 反思式进化：GEPA

### 44.7.1 方法

GEPA（Agrawal 等，ICLR 2026）把反思式改写和进化搜索结合起来，优化多模块程序的指令。按原文的描述，它维护一个候选程序池，反复做下面的事：

1. **选父代**：按"实例级帕累托前沿"（下面定义）从池里随机选一个候选。
2. **反思式变异**：挑一个模块（原文按轮转的顺序挑，使每个模块都有机会被改），在一小批训练案例上运行父代，收集执行迹和评价反馈。指标除了分数还可以返回文字，例如"读取器把'下面几颗流水了'当成了没有腐烂"。让语言模型读这些材料，为这个模块写一条新指令。
3. **小批量筛选**：新候选在同一小批上比父代好，才拿到另一份数据（原文记为 $D_{\text{pareto}}$）上逐个案例评估，并加入池中。
4. **合并**：有时把两个候选中各自演化过的不同模块拼在一起，作为一种交叉。

原文与强化学习方法 GRPO 和 MIPRO 的后续版本比较，报告 GEPA 在多个任务上用少得多的推演次数取得了更好的成绩；预印本前后两个版本给出的幅度不同，以正式版为准。

### 44.7.2 实例级帕累托前沿

只保留平均分最好的候选，会让搜索很快收窄到一条路线上。GEPA 的选择规则保留了在**某些案例上**最好的候选。

**定义 44.7（实例级帕累托前沿）** 设候选 $1,\dots,N$ 在案例 $i=1,\dots,m$ 上的分数为 $s_j(i)$。候选 $j$ **支配**候选 $k$，如果对每个 $i$ 都有 $s_j(i)\ge s_k(i)$，且至少一个不等号严格。**实例级帕累托前沿**是在至少一个案例上取得 $\max_ks_k(i)$、且不被任何候选支配的候选集合。前沿的**覆盖率**是

$$
\mathrm{cov}=\frac1m\sum_{i=1}^m\max_js_j(i).
$$

**怎么读**：把每个案例当成一个目标，这就是后面讲多目标时的帕累托支配，只不过目标有 $m$ 个。GEPA 按"在多少个案例上领先"的比例从前沿中抽父代。覆盖率是"每个案例都用在它上面最好的候选"时的成绩。

**命题 44.5（前沿的覆盖率）** （1）$\mathrm{cov}\ge\max_j\frac1m\sum_is_j(i)$，即覆盖率不低于最好的单个候选的平均分。（2）设分数取 0/1，各候选在案例 $i$ 上相互独立地以概率 $q_i$ 得 1，则

$$
\mathbb{E}[\mathrm{cov}]=\frac1m\sum_{i=1}^m\Big(1-(1-q_i)^N\Big).
$$

**怎么读**：代入 $m=100$ 个案例，一半容易（$q_i=0.9$）、一半难（$q_i=0.5$），10 个候选的真实准确率都是 $0.7$。覆盖率的期望是 $0.5(1-0.1^{10})+0.5(1-0.5^{10})\approx0.9995$，而单个候选的期望准确率只有 0.7。模拟 2 万次，10 个候选中经验准确率最高的那个平均是 0.763，比真实值高出 0.063；10 个候选全部在前沿上。

#### 证明（第一遍可以跳过）

（1）对每个 $j$ 和 $i$，$\max_ks_k(i)\ge s_j(i)$，对 $i$ 求平均即得，再对 $j$ 取最大。（2）$\max_js_j(i)$ 是 0/1 变量，等于 1 当且仅当至少一个候选得 1，概率 $1-(1-q_i)^N$；由期望的线性性对 $i$ 求平均。$\square$

**怎么用**：这个命题说明两件事。第一，前沿保留多样性：彼此成绩相当、只在不同案例上偶然领先的候选都会被保留，这正是它的目的，第 29 章 pass@k 的计算在这里换成了"每个案例上至少一个候选对"。第二，覆盖率不是任何一个程序的成绩，它是一个"知道每个案例该用哪个候选"的神谕的成绩；最终交付的必须是一个候选，它的成绩要在另一份数据上重估。在 $D_{\text{pareto}}$ 上逐个案例的分数被用来选父代，这份数据就成了第 5 章意义下被反复查询的留出集，挑出来的最好候选在它上面的成绩偏乐观（上面的 0.063），交付前还需要一份没被用过的测试集。

### 44.7.3 同一族的其他方法

用语言模型做变异算子、用评估器做选择的进化搜索，也被用在一般的程序上。FunSearch（Romera-Paredes 等，*Nature* 2024）让语言模型改写一段打分程序，由自动评估器筛选，用于组合数学问题的构造；AlphaEvolve（Novikov 等，2025）把这一思路扩展到更一般的算法与代码。还有直接搜索程序**结构**的方法：ADAS（Hu、Lu、Clune，ICLR 2025）让一个"元智能体"用代码写出新的智能体设计，AFlow（Zhang 等，ICLR 2025）用蒙特卡洛树搜索在以代码表示的工作流上搜索。结构也是参数，只不过 $\Theta$ 更大，命题 44.3 和 44.4 同样适用，看过的数据同样只能当设计集。

### 小结

这一节说的是：GEPA 轮流对模块做反思式改写，在小批量上筛选，按实例级帕累托前沿选父代，并合并不同候选的模块；前沿的覆盖率不低于最好的单个候选，在噪声下可以远高于任何候选的真实成绩（命题 44.5），它保留多样性，但不是可以交付的成绩。

## 44.8 程序出错时改哪个模块

### 44.8.1 问题

程序在验证集上代价太高，下一步改哪个模块？读取器的错误率最高的那个，不一定是最该改的：一个模块读错的案例里，有些结论根本不依赖它（不关键），有些错误要和另一个模块的错误凑在一起才会造成判错。

第 31 章把这个问题当作诊断：命题 31.11 说，只看读数和结论，读错、缺事实、规则错三类部件各自都能单独说得通；命题 31.12 说，核实事实之后才能确定地排除一部分。第 36 章命题 36.7 回答了"这一单是谁造成的"。这一节要的是第三个量：**在整批案例上，修好哪个模块能省下多少代价**。它决定资源往哪里投。

### 44.8.2 模块替换

有核实数据时，可以直接量：把模块 $j$ 的输出换成核实过的正确值，重新运行后面的部分，看代价降了多少。

**定义 44.8（模块替换值）** 设模块集合为 $N$，在一份核实过中间值的数据上，对 $T\subseteq N$，记 $V(T)$ 为把 $T$ 中模块的输出全部换成正确值后程序的总代价，令 $v(T)=V(\varnothing)-V(T)$，即替换 $T$ 能省下的代价。

例子：在时限内的 100 个案例，两个读取模块 $R_b$（腐烂）和 $R_p$（渗汁），规则丙，标签与规则丙在真实事实上一致。真实事实与读错的分布：

| 真实 $(b,p)$ | 案例数 | 只有 $R_b$ 读错 | 只有 $R_p$ 读错 | 两个都读错 |
|---|---|---|---|---|
| (1,1) | 10 | 1 | 1 | 2 |
| (0,0) | 40 | 3 | 1 | 1 |
| (1,0) | 40 | 6 | 0 | 0 |
| (0,1) | 10 | 0 | 4 | 0 |

用 Python 逐案计算：$V(\varnothing)=41$（17 个判错），$V(\{b\})=14$，$V(\{p\})=22$，$V(\{b,p\})=0$。于是 $v(\{b\})=27$，$v(\{p\})=19$，$v(\{b,p\})=41$。

**怎么读**：$(1,1)$ 格里只读错一个的案例，另一个读数仍是 1，规则仍判 S，读错不关键，不产生代价。两个都读错的 2 个案例判成 B，各代价 3；修好任何一个就够，两个模块是**替代**关系。$(0,0)$ 格里两个都误报的 1 个案例判成 S，要两个都修好才能判对，是**互补**关系。$R_b$ 读错 13 次、$R_p$ 读错 9 次，但读错次数和替换值不成比例，因为有些读错不关键。

### 44.8.3 交互项与 Shapley 分配

$v(\{b\})+v(\{p\})=46\ne41=v(\{b,p\})$。分别估计"修好每个模块能省多少"再相加，会高估同时修好两个的收益。

**命题 44.6（两个模块的替换分解）** 记交互项 $I=v(\{b,p\})-v(\{b\})-v(\{p\})$。则

$$
v(\{b,p\})=v(\{b\})+v(\{p\})+I,
$$

两个模块的 Shapley 值（定义 8.3，以 $v$ 为合作博弈）是

$$
\psi_b=v(\{b\})+\tfrac12I,\qquad \psi_p=v(\{p\})+\tfrac12I,
$$

二者之和等于 $v(\{b,p\})$。逐案看，替代关系的案例使 $I$ 减小，互补关系的案例使 $I$ 增大。

**怎么读**：例子中 $I=41-27-19=-5$：替代的 2 个案例贡献 $-6$（每个案例本应各算一次 3，却在两个单独替换里各被算了一次），互补的 1 个案例贡献 $+1$。Shapley 值 $\psi_b=24.5$，$\psi_p=16.5$。先改 $R_b$ 的理由很清楚：它单独能省 27，按 Shapley 也分到较多。

#### 证明（第一遍可以跳过）

第一式是 $I$ 的定义。两个玩家时，Shapley 值是两种加入顺序下边际贡献的平均：$\psi_b=\frac12\big[v(\{b\})-v(\varnothing)\big]+\frac12\big[v(\{b,p\})-v(\{p\})\big]$。$v(\varnothing)=0$，第二项等于 $v(\{b\})+I$，所以 $\psi_b=v(\{b\})+\frac12I$；$\psi_p$ 对称。相加得 $v(\{b\})+v(\{p\})+I=v(\{b,p\})$。逐案的说法：$V(T)$ 是各案例代价之和，$I$ 也是各案例交互项之和；替代案例的代价 $c$ 在 $v(\{b\})$、$v(\{p\})$、$v(\{b,p\})$ 中各出现一次，交互项为 $c-2c=-c$；互补案例只在 $v(\{b,p\})$ 中出现，交互项为 $+c$。$\square$

### 44.8.4 没有核实数据时

模块替换需要中间值的金标。没有金标时，只能用代理：优化器让语言模型读执行迹指认"哪一步错了"，或者像第 32 章那样按模块统计频谱。这些都只是提议，正确与否要靠核实一小部分案例来检验，下一步核实哪些案例可以按第 31 章的熵或第 18 章的读取价值来选。另一个便宜的办法是做**关键性检查**：把模块在某个案例上的输出改成另一个值，看结论是否改变（定义 44.4）。它不需要金标，能把"不关键的读错"从候选里排除，剩下的才值得花钱核实。

### 小结

这一节说的是：有核实数据时，把模块输出换成正确值、看代价省下多少，是最直接的功劳度量；单独替换的收益相加会因替代与互补关系而偏离联合收益，Shapley 值把交互项平分（命题 44.6）；没有金标时，模型的指认和频谱只是提议，关键性检查可以先排除一部分。

## 44.9 读取器与规则：联合优化还是分开优化

### 44.9.1 端到端优化会发生什么

44.3 节已经看到，自举在案例 3、6 上奖励读错。如果优化器足够强，能把读取器调成"对训练案例输出任何想要的值"，会怎样？

**命题 44.7（端到端优化把读数推向结论）** 固定规则 $g$，其余事实读对，记案例 $i$ 的其余事实为 $w_i$、真实的 $b$ 为 $b_i$。设训练案例的原始输入两两不同，读取器可以是从原始输入到 $\{0,1\}$ 的任意函数 $r$，目标是 $\hat J(r)=\frac1n\sum_ic\big(y_i,g(w_i,r(x_i))\big)$。则：

1. $\min_r\hat J(r)=\frac1n\sum_i\min_{v\in\{0,1\}}c\big(y_i,g(w_i,v)\big)$；
2. 在任一最小值点，凡满足 $c(y_i,g(w_i,1-b_i))<c(y_i,g(w_i,b_i))$ 的案例，都有 $r(x_i)=1-b_i$，即读错；
3. 这个最小值可以严格低于真实事实上的碰撞下界 $L_\phi(S)$；
4. 若目标改为 $\hat J(r)+\frac\lambda n\sum_i\mathbf{1}[r(x_i)\ne b_i]$（$b_i$ 为金标），则在最小值点，案例 $i$ 被读错当且仅当 $c(y_i,g(w_i,b_i))-c(y_i,g(w_i,1-b_i))>\lambda$（相等时两者皆可）；特别地，$\lambda\ge C$ 时存在不读错任何案例的最小值点，$\lambda>C$ 时每个最小值点都不读错。

**代入例子**：8 个案例，规则甲，第 1 章的代价矩阵。案例 3 读错能把代价从 1 降到 0，案例 6 读错能从 3 降到 0，其余案例读对已是 0。端到端最优的读取器在案例 3 读 0、案例 6 读 1，训练代价为 0；而真实事实 $(a,b)$ 上的碰撞下界是 $3/8$（规则乙达到它）。读取器与金标 $b$ 的一致率从 1 降到 $6/8$。它读出的不再是"是否腐烂"，而是"在时限内时，结论是否为 S"，正是命题 8.5 说的夹带结论的事实。加上惩罚后：$\lambda<1$ 时两个都读错，$1<\lambda<3$ 时只有案例 6 被读错，$\lambda>3$ 时都读对。

#### 证明（第一遍可以跳过）

**思路**：原始输入两两不同，读取器在每个案例上的输出可以独立选择，目标就拆成了逐案的最小化。

1. 因为 $x_i$ 两两不同，任意一组值 $(v_1,\dots,v_n)$ 都能由某个函数 $r$ 实现。$\hat J$ 是逐案代价之和，每一项只依赖 $v_i$，所以总和的最小值等于逐项最小值之和，这是第 1 条。
2. 若某最小值点在满足条件的案例上取 $r(x_i)=b_i$，把它改成 $1-b_i$，只有这一项变化且严格下降，与最小性矛盾，这是第 2 条。
3. 例子即为第 3 条的实例：训练代价 0 而 $L_\phi(S)=3/8$。原因是碰撞下界针对"只看真实事实的规则"（命题 1.9），而读错后的读数是原始输入的函数，不再只看真实事实。
4. 加惩罚后仍可逐案最小化：读对的代价为 $c(y_i,g(w_i,b_i))$，读错为 $c(y_i,g(w_i,1-b_i))+\lambda$，读错严格更优当且仅当差值大于 $\lambda$。代价取值于 $[0,C]$，差值至多 $C$；$\lambda\ge C$ 时读对不劣于读错，逐案取读对得到一个最小值点；$\lambda>C$ 时读对严格更优。$\square$

**怎么读**：真实的优化器不会把读取器调成任意函数，原始输入也会有相似的案例，所以实际情形介于两端之间。但方向是确定的：只要读取器的参数是对着最终结论优化的，它就会被推向"在碰撞案例上按标签读"。碰撞案例恰好是第 1 章说需要新事实或复核标签的地方；端到端优化把这些信号藏进了读取器，训练代价变好看了，碰撞组却消失了。上一章讲过"对着结论标签优化读取提示词"的泄漏，这里在程序级上更隐蔽：读取器的提示词里一个标签也没有，泄漏是通过优化器发生的。

### 44.9.2 分开优化的保证

另一条路是**分开**：读取器对着事实的金标优化，目标是测量效度（第 15、18 章）；规则在读数上学，目标是结论的代价。分开优化放弃了一部分训练代价，换来一个不依赖标签的保证。

**引理 44.8（模块化误差分解）** 设代价取值于 $[0,C]$，$\phi$ 为真实事实，$\hat\phi$ 为读数，$g$ 为任一规则。则

$$
\begin{aligned}
\big\lvert R(g\circ\hat\phi)-R(g\circ\phi)\big\rvert&\le C\Pr\big(g(\hat\phi(X))\ne g(\phi(X))\big)\\
&\le C\Pr\big(\hat\phi(X)\ne\phi(X)\big).
\end{aligned}
$$

**怎么读**：第一个不等式右边的概率是"读错且关键"的比例，第二个是"读错"的比例。代入 44.8 节的例子：$C=3$，两个读取器至少一个读错的案例共 19 个，其中改变了结论的 17 个，所以两个上界分别是 $3\times0.17=0.51$ 和 $3\times0.19=0.57$；实际的变化是 0.41（真实事实上规则丙的代价为 0）。这个界的意义不在于紧，而在于**它的右边可以在金标事实上估计，不需要结论标签，也和规则怎样学无关**。读取器的误差率是一个可以单独标定、单独监控的量，规则的风险是另一个量，两者相加就控制了整个程序。端到端优化得到的读取器没有这样的分解：它的"误差"一部分是故意的。

#### 证明（第一遍可以跳过）

在事件 $g(\hat\phi(X))=g(\phi(X))$ 上，两个程序的代价相同；在其补集上，两个代价都在 $[0,C]$ 中，差的绝对值不超过 $C$。所以 $\big\lvert c(Y,g(\hat\phi(X)))-c(Y,g(\phi(X)))\big\rvert\le C\,\mathbf{1}[g(\hat\phi(X))\ne g(\phi(X))]$，取期望并用 $\lvert\mathbb{E}Z\rvert\le\mathbb{E}\lvert Z\rvert$ 得第一个不等式。第二个：$\hat\phi(X)=\phi(X)$ 时 $g$ 的输出相同，所以前一事件包含于后一事件。$\square$

把 8 个案例上的两种做法放在一起：

| | 联合优化（只看结论） | 分开优化 |
|---|---|---|
| 读取器的目标 | 结论代价 | 与事实金标一致 |
| 读取器与金标 $b$ 的一致率 | $6/8$ | $1$ |
| 训练代价 | 0（规则甲） | $3/8$（规则乙） |
| 碰撞下界给出的证书 | 无（读数不再是事实） | $3/8$，在 $(a,b)$ 上已经最优 |
| 碰撞组 $\{1,2,3\}$、$\{4,5,6\}$ | 被读取器"消化"掉 | 保留，送去找新事实（例如 $p$）或复核 |

分开优化在训练集上差了 $3/8$，但这 $3/8$ 是诚实的：它告诉我们"只靠 $a,b$ 做不到更好"，第 1 章 1.10.5 节加入 $p$ 以后才降到 $1/8$。

### 44.9.3 与两条路线的关系

第 28 章 28.10 节比较了"模型提谓词、搜索去组合"（路线甲）和"模型直接写规则或程序"（路线乙）。放到本章的语言里：

- 路线甲是**分开优化**：谓词的读取按信度和效度检查，规则由有证书的算法在读数上学，碰撞下界给出"在这些事实上已经最优"的证书。
- 端到端的程序优化是**联合优化**：所有模块对着同一个最终指标调。路线乙是它的一个极端，规则和读取都写在一段程序里。由命题 28.7，这样的程序仍然可以拆成原子判断，拆开以后就能按命题 44.7 检查：每个读取模块在金标上的一致率是否因为优化而下降？

实际可行的是一个折中。读取器**只**用事实金标和读取的通过标准来优化，这一步可以用本章任何一种方法，指标换成"与金标一致"即可；规则在读数上学；如果要端到端微调，就把读取器与金标的一致率作为约束或惩罚（命题 44.7 第 4 条），惩罚系数取到最大代价 $C$ 以上，读取器就没有动机故意读错。碰撞组则照第 28 章的做法，送去提出新事实或复核标签，而不是交给读取器去"消化"。

### 小结

这一节说的是：只对着最终结论联合优化读取器和规则，最优的读取器会在碰撞案例上按标签读错，训练代价可以低于真实事实上的碰撞下界（命题 44.7）；分开优化时，读取误差（更准确地说，读错且关键的比例）乘以最大代价，就是成绩损失的上界，可以不用结论标签估计（引理 44.8）；折中的做法是读取器对着事实金标优化，联合微调时以足够大的系数惩罚与金标的不一致。

## 44.10 把成本放进目标

### 44.10.1 不只是准确率

程序的每个模块都可以换成更大或更小的模型、更长或更短的示例列表。成绩只是一个维度，另外两个维度同样实在：每单的**调用成本**和**转人工率**。本章介绍的方法，原文的主要目标都是任务指标；成本通常由人事先固定模型选择来控制。把成本放进目标，就成了后面讲多目标搜索时的问题，这里只看一个例子。

### 44.10.2 一个级联的例子

读取"是否腐烂"有四种程序（调用成本以小模型的一次调用为 1 个单位，大模型一次 10 个单位；平均每次读错的代价为 2，与 44.5 节相同）：小模型在八成案例上很有把握，读错率 3%，其余两成读错率 25%；大模型在这两部分上的读错率分别是 1% 和 10%。

| 程序 | 每单代价 | 每单调用成本 | 转人工率 |
|---|---|---|---|
| P1：只用小模型 | 0.148 | 1 | 0 |
| P2：只用大模型 | 0.056 | 10 | 0 |
| P3：小模型没把握时再问大模型 | 0.088 | 3 | 0 |
| P4：小模型没把握时转人工（每单 0.3） | 0.108 | 1 | 20% |

**怎么读**：只看代价和调用成本两个维度，P1 被 P4 支配（成本相同，代价更高）；把转人工率也当作目标，P1 仍在前沿上，因为它不占用人工。若把调用成本按每单位 $\lambda$ 折算加进目标，最小化"代价 $+\lambda\times$ 调用成本"：$\lambda<0.0046$ 时选 P2，$0.0046<\lambda<0.01$ 时选 P3，$\lambda>0.01$ 时选 P4。两个分界点是相邻程序之间的交换率：P3 比 P4 少 0.02 代价、多 2 个单位，$0.02/2=0.01$；P2 比 P3 少 0.032、多 7 个单位，$0.032/7\approx0.0046$。转人工率是第三个维度：如果人工每天只能处理一成的单量，P4 就不可行，只能在 P1、P2、P3 之间选：$\lambda<0.0046$ 时仍选 P2，$\lambda$ 介于约 0.0046 与 0.03 之间时选 P3，超过 0.03 时选 P1（$0.06/2=0.03$ 是 P3 与 P1 的交换率）。级联的思路在 FrugalGPT（Chen、Zaharia、Zou）中被系统地研究过，它学习对每个问题按什么顺序调用哪些模型。

在程序优化里，模型选择就是 $\theta_j$ 的一部分，上面四个程序是同一个参数空间里的四个点。把成本写进 $\mu$，前面的命题全部照用；只是加权和只能找到帕累托前沿上"凸"的那部分，这个问题后面讲多目标时会证明。级联还有一个和 44.9 节相关的细节：小模型"有没有把握"由它自己的输出概率决定，这需要校准（第 7 章），否则级联会把错误的读数当作有把握的读数放行。

### 小结

这一节说的是：调用成本和转人工率是与准确率并列的目标；模型选择、示例长度和级联结构都是程序参数，按折算率加权时，不同的折算率选出不同的程序，转人工能力是一个硬约束。

## 44.11 评估与报告

把本章的方法用在售后系统上，至少要分清下面几份数据和几件事。陷阱的完整目录放在本卷最后一章，这里只列与程序优化直接相关的。

1. **数据的用途**：自举示例与反思反馈用的**设计集**（看了什么都可以）；小批量筛选和代理模型用的**选择集**（最好只返回采纳决定，按第 5 章 5.10 节记比特）；实例级前沿用的数据（逐案分数被反复使用，属于选择集，而且是泄露较多的那种）；**封存的测试集**。同一买家、同一订单的改写放在同一份里（第 4 章）。
2. **预算**：程序运行次数、优化器自己的模型调用次数和词元数、每单使用时的调用数，分开报告。不同方法要在相同预算下比较。
3. **随机性**：同一方法换随机种子、换训练案例的抽样，结果的波动有多大。报告多次运行的分布，而不是最好的一次。
4. **模块级的报告**：每个读取模块在事实金标上的一致率和 $\kappa$，优化前后各一次（命题 44.7 的检查）；优化后的指令和示例全文，以及新的读取器身份（定义 18.1：任何一项变了都是另一台仪器）。
5. **交付的是一个程序**：报告这个程序在测试集上的成绩及区间，不报告前沿覆盖率或"最好的一次小批量成绩"。

### 小结

这一节说的是：程序优化的评估要按用途分开设计集、选择集和测试集，在相同预算下比较，报告多次运行的波动和模块级的金标一致率，交付并评估一个程序。

## 44.13 本章小结

- LLM 程序由带签名的模块和代码组成，参数是各模块的指令、示例、模型选择和代码常数；程序优化是在乘积空间上最小化经验风险，只有最终结论有标签（44.1 节）。
- DSPy 让优化器按数据生成各模块的提示，核心是从成功运行中自举示例；MIPRO 自举示例候选、有根据地提议指令候选，用 TPE 代理模型在组合上搜索；TextGrad 与 Trace 让语言模型读计算图或执行迹和反馈，写出修改；GEPA 轮流反思式改写模块，按实例级帕累托前沿选父代，并合并模块（44.2、44.4、44.6、44.7 节）。
- 自举在不关键的案例上放过错误、在标签与规则不一致的关键案例上奖励错误（命题 44.1、推论 44.2）。
- 块坐标优化在精确评估下有限步停在块坐标局部最优，可能卡在接口耦合处（命题 44.3）；含噪评估要用新的小批量和门槛 $\eta>\varepsilon$（命题 44.4）。
- 前沿覆盖率不低于最好的单个候选，在噪声下远高于任何候选的真实成绩（命题 44.5）。
- 模块替换值度量修好一个模块能省多少，交互项来自替代与互补，Shapley 值把它平分（命题 44.6）。
- 只对着结论联合优化，读取器会在碰撞案例上按标签读错，训练代价可低于碰撞下界（命题 44.7）；分开优化时，读错且关键的比例乘以最大代价控制成绩损失（引理 44.8）。
- 成本与转人工率是与成绩并列的目标；评估要分开数据用途、对齐预算、报告波动和模块级金标一致率（44.10、44.11 节）。

<details>
<summary>练习 44.10</summary>

（1）若成绩对两个模块是可加的，$f(\theta_1,\theta_2)=f_1(\theta_1)+f_2(\theta_2)$，而父代 A 改进了模块 1、父代 B 改进了模块 2（相对同一祖先），合并后的程序同时拥有两个改进，不比任何一个父代差。可加性不成立时没有这个保证。（2）一个例子：祖先的读取器输出"是/否"，规则用关键词解析。父代 A 只改了读取器，让它输出"1/0"并改进了判断标准，旧的关键词解析器恰好也认得"1/0"，成绩变好。父代 B 只改了规则，把解析器改成只接受"是/否"、其余一律转人工，这对祖先的读取器有好处（偶尔出现的含糊措辞被转人工而不是被误解析），成绩也变好。合并得到"输出 1/0 的读取器 + 只接受是/否的解析器"，每一单都解析失败、转人工，每单代价 0.3，比两个父代都差。这和 44.5.1 节一样，是接口两侧各自演化造成的耦合。（3）在一小批案例上计算四个组合（祖先、只换 1、只换 2、都换）的成绩，估计交互项 $f(\text{都换})-f(\text{只换1})-f(\text{只换2})+f(\text{祖先})$，和命题 44.6 的交互项是同一个量；交互项显著时，合并后要单独评估，不能按可加推断。

</details>
