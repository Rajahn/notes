# 从模型能力到系统能力 六期文档分享总纲

[返回系列目录](README.md)

这组六期文档围绕同一个问题展开：一个模型具备的能力，怎样成为系统持续、可靠地解决现实问题的能力？

系列总题为《从模型能力到系统能力》，副题为《AI 应用中的表征、计算与学习》。六篇依次为表征、语言、计算、认识、因果与实验、学习。前三篇研究问题怎样被构造和求解，后三篇研究判断、改动与能力积累怎样获得根据。

六篇正文已完成，合计约 3.6 万汉字。下方目录可以直接进入各期文档；后续部分保留写作总纲，便于查看中心命题、章节安排、主要案例和承接关系。

## 文档形式与系列开篇

每篇写成能够独立阅读的完整文章，默认面向有软件工程背景、接触过大模型应用、尚未系统学习形式化方法和因果推断的读者。正文建议约 5000 至 7000 字；较长证明、代码和实验细节放在可选附录。术语在解决具体问题时引入，图表和公式的含义在正文中完整解释。

第一篇包含系列总引。开头以人机协作的形式化数学成果与应用落地的困难形成问题意识，随后落到表征。总引需要说明：一次高度投入、可以严格核验的成功，与在有限预算下反复处理新材料的稳定表现，要求不同的求解条件。

可使用的事实是：2026 年 11 月 20 日，Levent Alpöge 发布了与 Claude 协作得到的黎曼猜想证明；11 月 21 日，Lean FRO 与 Mathlib Initiative 发布联合声明，确认形式化命题与证明的正确性。声明同时说明，核验包括目标命题的一致性和证明本身的有效性。参见[作者说明](https://alpo.ge/remark.pdf)及[联合声明](https://leanprover-community.github.io/blog/posts/riemann-hypothesis/)。

这为系列提出一个持续的问题：我们交给系统的对象、表达、计算与检查，是否确实对应了现实中的目标。总引纳入第一篇，不另设第七篇。

## 第一期 表征

### 我们究竟把什么交给了 AI

本篇回答：系统必须保留什么，才有可能作出需要的判断？

中心命题是：表征保留或抹去的区别，会限制后续判断；即使信息相同，组织方式也会改变利用信息的计算成本。表征的选择需要同时考虑任务、可用操作和获得这些信息的代价。

#### 章节安排

1. **模型很强与应用困难为何可以同时存在。** 从系列总引进入一个具体接口：系统实际收到了哪些材料，中间又留下了什么。把“能力不足”拆成可以追查的问题。

2. **两个不同的问题怎样变成同一份数据。** 用“衣身完整但吊牌有孔”与“衣身有孔但吊牌完整”构成反例对。如果都被压成“有衣服、有孔洞”，仅接收这两个字段的下游系统无法同时答对。明确当前只判断衣身是否有孔，不直接作最终责任判断。

3. **属性为什么必须有归属。** 从全局布尔量推进到对象、部件、关系和证据位置，解释对象绑定怎样改变能作出的判断。

4. **信息相同为何仍有计算差别。** 比较散落在文本中的依赖关系和显式依赖图，说明表示与操作要共同考虑。图、表、文字、向量和程序分别适合哪些操作。

5. **怎样评价一种表征。** 检查它是否保留任务相关区别、支持需要的查询与修改，以及新增提取、维护和计算成本是否值得。引出反例驱动的表征修订。

主要案例为衣身与吊牌；跨域案例为检索摘要丢失版本与能力的归属，进而把个人版 v1 的能力安到企业版 v2 上。两者共同说明关系丢失，不要求读者了解具体判责规则。

技术核心是任务相关的不可区分性：若两个输入得到同一表示，但要求不同答案，仅依赖该表示的决策不能同时正确。回读原材料会扩展可用信息，属于新的信息条件。

本篇让读者能够检查一个接口是否删除了关键区别。自然延伸的问题是：一种分类使什么变得可见，又让什么差异消失？

关于信息等价与计算效率的区别，可用 Larkin 与 Simon 的 [Why a Diagram is Sometimes Worth Ten Thousand Words](https://iiif.library.cmu.edu/file/Simon_box00014_fld00953_bdl0001_doc0001/Simon_box00014_fld00953_bdl0001_doc0001.pdf)作为研究支点。其分析强调表示及作用于表示的操作，不能直接推成所有模型都受益于更多结构。

篇末承接：确定了需要保留的对象和关系，下一步是怎样把它们组织成可组合、可解释、可执行的表达。

## 第二期 语言

### 怎样让意图成为明确的表达

本篇回答：一段表达究竟规定了什么，以及复杂要求怎样由较简单的部分组合而成？

中心命题是：语言为表达的组合与解释建立约定。形式化可以固定已经作出的解释、支持检查和执行；模糊要求的含义仍需要结合任务与情境确定。

#### 章节安排

1. **一句大家都看懂的话为何产生不同实现。** 以会议助手的要求开篇：安排半小时讨论，主要参与人都能来，尽量照顾时区，先给方案。逐步区分事实、硬约束、偏好与行动范围。

2. **语法 语义与语境。** 解释表达是否合法、表达是什么意思、当前情境下如何理解。用“满足 A 或 B 且 C”呈现组合范围的影响，用具体日期和单位说明类型约束的作用。

3. **组合怎样产生复杂能力。** 从命名、变量和作用域，讲到条件、关系、状态与动作。用一个很小的表达体系说明复杂行为如何由部件构成。

4. **表达能力与可分析性如何取舍。** 对比规则表达式、查询语言与通用程序，讨论局部修改、依赖追踪和静态检查的条件。是否图灵完备不能替代具体的语言设计判断。

5. **人和机器怎样维持共同含义。** 讨论自然语言说明、形式表达、例子和反例怎样互相校对。概念发生变化时，接口和历史规则如何同步修订。

主要案例为会议助手，跨域案例为自然语言转 SQL 时的分组、并列、空值与范围解释。DSL 可以作为一种具体选择出现，但本篇的判断标准是语义和需要支持的操作。

技术核心是组合语义与作用域。读者读完应当能分辨：当前困难来自表达缺口、语义不明确，还是执行方式。

关于编程语言表达能力的比较，可用 Felleisen 的 [On the Expressive Power of Programming Languages](https://www.cs.tufts.edu/~nr/cs257/archive/matthias-felleisen/expressive-as-published.pdf)作为研究支点。它提供比只比较可计算函数集合更细的分析角度。

本篇的人文问题来自实际解释过程：谁决定“必须”“允许”“优先”的含义，形式化时又作出了哪些取舍？

篇末承接：表达已经清楚，找到满足这些要求的答案还需要怎样的计算。

## 第三期 计算

### 怎样在有限资源中解决问题

本篇回答：为什么知道什么样的答案合格，仍不等于能够以可接受的成本找到它？

中心命题是：问题的表达、可求解性和求解成本需要分别分析。模型、搜索算法与专门求解器承担不同的工作，选择依据是任务结构和资源约束。

#### 章节安排

1. **从一次会议扩展到一天的排程。** 延续第二篇的场景，增加场次、讲者、房间、冲突和偏好。输入和规则暂时固定，观察组合数量怎样增长。

2. **搜索怎样利用问题结构。** 比较枚举、约束传播、剪枝、分解和缓存。每个方法都对应一个明确的可利用结构。

3. **会描述 能求解与能高效求解。** 用必要的篇幅区分可计算性、复杂性以及有限实例的难度。最坏情况困难不等于每个实际实例都难，某次成功也不能推出一般高效算法。

4. **模型与算法怎样分工。** 讨论模型提出候选、识别模式或解释要求，程序执行确定操作，求解器处理适合其假设的约束。输入翻译和结果核对的成本一并计算。

5. **什么时候值得继续计算。** 比较更长推理、增加候选、追加信息、直接调用工具等选择，讨论最优、足够好与停止条件。以总成本和可验证的收益评价计算投入。

主要案例为研讨会排程，跨域案例为同一数据库查询的不同执行计划。原业务中的规则组合与读取预算只作短例，说明选算法的思路可以迁移。

技术核心是搜索空间、约束传播和计算预算。技术附录可补充 SAT 或 SMT 的极小例子，以及验证候选与发现候选的区别；正文保持在一个问题上逐层推进。

读者读完应当能够问清：增加计算究竟在搜索什么，哪些结构已经可以交给现成算法，什么成本尚未被计入。

Russell 与 Wefald 的 Principles of Metareasoning 可作为本篇研究支点。[Russell 的作者说明](https://people.eecs.berkeley.edu/~russell/research-bo.html)将计算步骤的选择与其对最终决策的预期改善联系起来，也指出精确优化元推理本身具有计算代价。

哲学问题是有限理性：时间和资源有限时，怎样给出有根据的行动与停止方式。

篇末承接：前面暂时接受输入和规则已经给定，第四篇开始检验它们如何与现实建立可靠联系。

## 第四期 认识

### 从观察到有根据的判断

本篇把观察与验证放进同一个更高层的问题：一个计算结果凭什么值得接受？

中心命题是：判断的可信程度取决于证据来源、成立前提、推导过程和适用范围。验证的意义取决于它检查了什么，以及检查所需的条件是否成立。

#### 章节安排

1. **六篇文章是否就是六份证据。** 从研究助手的资料整理开篇：多个网页可能转述同一个原始来源。追踪来源依赖，区分文本数量与证据强度。

2. **系统观察到了什么 又推断了什么。** 区分原始材料、读取结果、背景假设与最终判断。以照片为例解释“未拍到”“看不清”“没有发现”和“有充分依据否定”的差别。

3. **不确定性为什么需要保留。** 讨论未知、冲突、模型误读和规则不明确，说明它们对应不同的后续动作。模型自报置信度需要经验校准，不能直接视为正确概率。

4. **验证究竟验证了哪一个命题。** 区分事实核对、推导检查、规格对齐和结果评估。形式系统执行正确，仍需核对规格与原始任务的对应；照片上的事实也需要各自的观察依据。

5. **下一份证据应该是什么。** 从现有判断的缺口出发，选择可能改变结论的查询或观察，并考虑获取成本。认识活动因此包含主动寻找反证和修订判断的能力。

主要案例为研究助手的来源追踪，跨域案例为多模态系统中的否定观察和未知。黎曼猜想证明中的命题核验可以再次短引，连接形式有效性与问题对齐。

技术核心是证据依赖、条件化判断、验证范围和信息价值。本篇终点是一条能说明根据与缺口的判断链，读者应能解释当前结论为何成立、依赖什么、还有什么未确定。

[Verified AI](https://berkeleylearnverify.github.io/VerifiedAIWebsite/)将环境建模、形式规格和计算引擎等列为不同挑战，可作为本篇技术背景。具体系统的保障始终要连同它的要求和环境假设来理解。

认识论在这里体现为一个工程问题：什么样的程序使一个判断有理由被接受，也有条件被纠正？

篇末承接：发现证据链有问题后，仍可能存在多个原因解释；第五篇研究如何通过干预区分它们。

## 第五期 因果与实验

### 怎样找到有效的改变

本篇回答：看到输出错误，怎样知道应该改哪里；看到结果变好，怎样知道改动为什么有效？

中心命题是：错误解释需要提出能够被检验的后果预期。通过受控干预比较竞争性假设，可以为下一步改动提供依据，但需要明确被固定和改变的条件。

#### 章节安排

1. **正确结果也可能来自错误抵消。** 用一个两阶段计算的构造例子起笔，让读者看到只修一个模块反而使最终结果变差的可能性。

2. **相关 依赖与因果分别回答什么。** 区分日志中一起出现的现象、逻辑上支撑结论的前提、软件模块替换的效果，以及现实世界事件之间的因果关系。

3. **怎样提出有区别的原因假设。** 将“模型不行”细化为观察误读、关系遗漏、规则不适用、组合方式出错等假设，并写出各自预期的干预结果。

4. **怎样设计能够区分原因的实验。** 介绍冻结输入、替换中间事实、观察与规则的四格回放、联合干预和交互效应。说明不同干预回答不同问题，不能将所有输出变化归入同一种原因。

5. **怎样从诊断走向修复。** 比较能解释错误的假设、实际可做的改动、预期影响范围与反例。检验一次修复是否在目标范围内奏效，并保留其成立条件。

下面是用于解释错误抵消的构造例子。正确任务为读取金额 80，再乘以系数 1。旧系统却读成 100，并用了 0.8，结果碰巧等于 80。

| 读取结果 | 旧系数 0.8 | 修正系数 1 |
| --- | --- | --- |
| 旧读取 100 | 80 结果碰巧正确 | 100 错误 |
| 修正读取 80 | 64 错误 | 80 正确 |

这个例子说明，单看最终对错无法判断内部机制是否正确，单独替换的效果也依赖另一模块。随后再连接到实际的取证与规则四格回放。跨域案例为同时更换检索器和生成提示词后，如何判断回答改善的来源。

技术核心是干预、反事实、受控比较和交互效应。软件内部的替换实验能回答指定系统在指定条件下如何响应；关于现实世界的因果结论，需要额外的模型和识别条件。多项改动存在交互时，不预设唯一的贡献百分比。

Pearl 的 [An Introduction to Causal Inference](https://ftp.cs.ucla.edu/pub/stat_ser/r354-reprint-corrected.pdf)可支撑关联、干预、反事实及其假设的区分；本篇围绕系统调试逐步引入这些概念。

本篇的终点是一项有明确证据和适用范围的局部改进。哲学问题是：一个经得起干预检验的解释，与一个听起来合理的叙述有什么不同？

篇末承接：一次改进成立之后，系统如何记住它、何时调用它，以及它能否帮助尚未遇到的任务。

## 第六期 学习

### 怎样让经验成为可复用的能力

本篇回答：系统反复尝试和修改，怎样才算积累了能力？

中心命题是：学习应体现在后续任务的行为变化中。一个经验单元的价值，要连同构建、检索、维护和误用成本，以及能力保持和跨任务迁移一起评价。

#### 章节安排

1. **系统一直在工作 却为什么总要从头开始。** 以代码修复 Agent 反复处理相似故障开篇，区分保存记录、检索旧答案与掌握具有适用条件的方法。

2. **哪些东西能够被学下来。** 讨论概念、表征、规则、搜索启发、操作程序和技能。明确学习可以体现为模型参数的变化，也可以体现为系统中可验证知识与程序的变化。

3. **经验怎样成为可调用的能力。** 为一个经验单元保留适用条件、所需输入、执行方式、预期结果、失败信号与验证办法。讨论如何组合小能力，以及何时需要拆分或重建它们。

4. **局部修复怎样成为持续改进。** 讨论有效分支的保留、失败反馈的利用、旧能力回归、负迁移、过期经验和知识淘汰。一次修改通过后，仍需判断它对其他任务的影响。

5. **怎样证明系统确实在学习。** 在未参与修订的新任务上比较成功率、总成本、所需尝试和旧能力保持，计入经验库管理成本。区分后续复用更便宜与学习新任务本身更高效这两类收益。

主要案例为代码修复 Agent，跨域案例为人学习数学方法：记住一道题的答案，与获得能够判断适用条件的方法，具有不同的迁移价值。原业务中“整棵候选被拒，但存在可保留的有效分支”可作为局部经验如何积累的补充例子。

技术核心是能力复用、迁移、保持与成本摊销。Sutton、Precup 与 Singh 的 [Between MDPs and semi-MDPs](https://ics.uci.edu/~dechter/courses/ics-295/winter-2018/papers/Sutton-Precup-Singh-AIJ99.pdf)为时间上延展的技能与规划提供了经典形式框架；实际 Agent 技能的效用仍需在具体任务上评价。

这一篇回到系列最长期的问题：哪些可复用的表征与操作，能够系统性地降低未来任务的学习和求解成本，这种收益在什么条件下能够持续？

结尾让学习回到前五篇：新经验可能要求重划概念、扩展语言、调整算法、改变观察方式和更新原因解释。人的目标选择、适用性判断与理解，也在这个循环中成为明确的讨论对象。

## 六篇之间的写作边界

| 相邻主题 | 前一篇主要解决 | 后一篇继续追问 |
| --- | --- | --- |
| 表征与语言 | 哪些对象和区别必须保留 | 怎样组合表达并赋予明确含义 |
| 语言与计算 | 什么算满足要求 | 怎样找到满足要求的答案 |
| 计算与认识 | 给定输入和规则怎样求解 | 输入、规则和结果凭什么适用于现实 |
| 认识与因果 | 一个结论有什么根据和缺口 | 哪种解释经得起干预检验，什么改动有效 |
| 因果与学习 | 一次改进如何获得证据 | 经验怎样保留、迁移并帮助未来任务 |

同一个例子可以跨篇出现，但每次回答新的问题。会议助手在第二篇承载语义，在第三篇承载搜索；判责案例在第一篇承载对象关系，在第四篇承载观察依据，在第五篇承载受控归因。

“系统能力”作为全系列的对象，比某一套工具或架构更宽。具体实现的选择，始终由要保存的信息、要支持的操作以及可获得的验证条件来说明。

## 统一写作方式

每篇从一个具体困惑出发，让主要案例贯穿论证。概念、公式与相关研究在解释确有需要时引入，随后换到第二个领域，检验读者能否迁移这一判断方式。

正文承担完整解释。关键假设与结论放在相邻段落，读者不需要额外口头说明。图表用于展示对象关系、条件变化、证据链或计算结果，图后的正文说明它究竟支持哪个判断。扩展推导和实现细节放入附录。

每篇结束时保留两项内容：一个可以用于自己项目的判断方法，以及一个由本篇结论自然产生的下一步问题。正文参考资料控制在两到四项，优先原始论文和官方材料，其他阅读放在扩展部分。

人文与哲学问题随着技术论证展开：表征涉及分类，语言涉及含义和规则，计算涉及有限理性，认识涉及证据与知识，因果涉及解释与科学方法，学习涉及能力、理解和认知的外部化。每个问题都保留具体的工程来源。

完成一篇后，检查它是否建立了一个清楚的判断，是否用案例说明判断为何成立，是否交代必要条件，以及是否使读者能够做出与阅读前不同的工程选择。
